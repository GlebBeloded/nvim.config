## Context
See proposal.md (Why) and the run's `root-cause.md`. These facts about Archon 0.11.1 shape the design:
- **Codex runs with no sandbox and no prompts.** Archon starts it with `sandboxMode: danger-full-access`, `networkAccessEnabled: true` and `approvalPolicy: never` as CLI flags. There is no config to change that.
- **`skills:` is ignored for codex.** Archon disables Codex's skill list (`skills.include_instructions=false`), so a skill loads only when the prompt names it as `$<skill>`.
- **Node fields:** `provider:` / `model:` / `effort:` are accepted per node, and the repo `assistant:` overrides the global `defaultAssistant`.

What Codex 0.153.4 itself loads:
- Repo skills from `.agents/skills` (the 10 `openspec-*` skills are already there and load), plus Codex plugins, whose skills are named `<plugin>:<skill>`.
- `AGENTS.md`, through its symlink.
- `codex plugin list --json` returns `{installed: [{name, installed, enabled, source: {path}}], available: [...]}`. `codex plugin add <plugin>@<marketplace>` installs a plugin, and `superpowers@openai-curated-remote` (6.4.2) is available.

## Goals / Non-Goals
**Goals:**
- Skills resolve on either provider under the same names. The preflight checks the provider that will actually run each node.

**Non-Goals:**
- Making Archon pass `skills:` to Codex. That is upstream behaviour.
- Per-node model tuning beyond review.

## Decisions
1. **Superpowers for Codex = the official Codex plugin `superpowers@openai-curated-remote`.** Its skills are named `superpowers:<skill>`, the same as in Claude, so workflows and commands keep one set of names.
   - Rejected: symlinking `~/.claude/plugins/cache/...` into `.agents/skills`. The path depends on the version, and the names would become `systematic-debugging` instead of `superpowers:…`.
   - Rejected: vendoring copies. They go stale.
2. **Load-first step names both forms.** The step says to load each skill with the Skill tool (Claude) or by invoking `$<skill>` (Codex), and to stop when one does not load. Naming `$<skill>` in the prompt is what Archon documents as the way a codex node loads a skill.
   - Rejected: per-provider command files. They would duplicate 10 commands.
3. **Preflight resolves per node provider.** `skills_check.py` computes each node's provider: `node.provider`, else the parent loop node's `provider`, else `assistant:` from `.archon/config.yaml`, else `claude`. It then checks that node's skills with the claude or codex resolver. It runs `codex plugin list --json` only when some codex node declares a plugin skill, and `claude plugin list --json` only when a claude node does.
4. **Setup installs Codex plugins from declared skills.** `skills_check.py --install-plugins .archon/workflows/*.yaml` (called by `make loop-setup`) installs the Claude plugins as before. For each `<plugin>` of a plugin skill declared on a codex node and not installed, it runs `codex plugin add <plugin>@openai-curated-remote`. The marketplace is one constant: Codex has no project-level plugin manifest like `.claude/settings.json`.
5. **Review on claude via `provider: claude` on the review node only.** That one line keeps review cross-model whichever default is set. `model:` is not set, so Claude uses its own default.
6. **Probe before the flip.**
   1. With `assistant: claude` still set, run a one-off `archon workflow run` with `--provider`/node override on codex against a throwaway workflow. It is not committed: its node loads `$superpowers:systematic-debugging` and `$openspec-explore` and runs `make quick`.
   2. Read the transcript.
   3. Only then commit the default change.

## Risks / Trade-offs
- [Codex model reads the `$skill` mention but does not open `SKILL.md`] → The load-first step asks it to report each loaded skill. The probe run checks this, and the cross-model review would flag a skipped discipline.
- [`openai-curated-remote` marketplace name or JSON shape changes in a later Codex] → The preflight fails loudly with the unresolved names, and `make loop-setup` is the fix path.
- [Codex runs unsandboxed] → This is the same trust level as Claude's `bypassPermissions` today. Documented, not changed.
- [Two copies of the openspec skills (`.claude/skills`, `.agents/skills`)] → Both are generated by `openspec`, and the preflight checks the copy the provider reads.

## Migration Plan
To roll back, change `assistant: codex` to `assistant: claude` in `.archon/config.yaml`.
