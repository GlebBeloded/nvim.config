## Context

See proposal.md (Why). The sources and pins are the ones in `diff-engine-lines` design.md (Context, Sources). This change reads, in `platform/util/diff/src/com/intellij/diff/comparison/`:
- `ByWordRt.kt`, `ByCharRt.kt`, `LineFragmentSplitter.kt` and `ChunkOptimizer.kt` (`WordChunkOptimizer`);
- `TrimUtil.kt` and `CharacterUtils.kt`.

It also reads `platform/diff-impl/src/com/intellij/diff/comparison/ComparisonManagerImpl.java` and the tests listed in Decision 7. Research, 2026-10-17:

- **Inner fragments in IntelliJ** (`ComparisonManagerImpl.createInnerFragments`):
  - A pure insertion or deletion gets an empty inner list when its text is equal under the policy (`isEqualTexts`), else no inner list.
  - Other fragments go through `ByWord.compareAndSplit` (words) or `doCompareChars` (chars). For chars that is `compareTwoStep`, `compareTrimWhitespaces` or `compareIgnoreWhitespaces`, by policy.
  - A `DiffTooBigException` keeps the fragment without inner fragments and counts a failure. After `DiffConfig.MAX_BAD_LINES = 3` failures, no more inner comparisons are tried.
  - Then `processBlocks`:
    - `squash` for every highlight mode except `BY_WORD_SPLIT`: adjoining fragments merge, and their inner ranges are shifted and joined.
    - `trim` for `IGNORE_WHITESPACES_CHUNKS`. That is already ported in `diff-engine-lines`; here it also honours `inner = {}`.
- **compareAndSplit:**
  1. Diff the words.
  2. Run `WordChunkOptimizer`.
  3. `LineFragmentSplitter` cuts the block at matched newlines and at matched first words of a line. It merges neighbouring chunks when neither has equal words, when both are whitespace-only, or when one has no words.
  4. Each sub-block gets its own delimiter and whitespace matching.
  - Example: `x\ny` vs `a\nb y` splits into two one-line fragments, while `x\ny` vs `a\nb` stays one (`SplitComparisonUtilTest`).
- **Tokens** (`ByWordRt.getInlineChunks`):
  - A word is a run of "alpha" code points: neither IntelliJ whitespace (space, tab, newline) nor ASCII punctuation, except `_`, which counts as alpha.
  - A continuous-script code point is a word of its own:
    - non-ASCII, not a decimal digit, and either outside the BMP, ideographic, or not alphabetic;
    - or Hiragana, Katakana, Thai or Javanese.
  - Newlines are their own chunks. Punctuation and spaces are no chunk; the matchers handle them.
- **Gaps in diffbandit** (`lua/diffbandit/diff/word_diff.lua`):
  - Missing: the TRIM and IGNORE whitespace matchers, `ByCharRt` beyond `comparePunctuation`, and the `isEqualTexts` check.
  - Wrong: `\r` counts as space, and `is_continuous_script` checks five hard-coded ranges. So emoji, `—`, `→` and NBSP join neighbouring words, where IntelliJ makes each one a word.

## Goals / Non-Goals

**Goals:**
- IntelliJ's inner highlights under every policy and highlight mode, matching its word, char and split test expectations.
- UTF-8-correct ranges that `diff-view` can hand straight to extmarks.

**Non-Goals:**
- Word-first mode, explicit ranges, ignored ranges and three-way word merges (proposal, Out of scope).
- Drawing anything (`diff-view`).

## Decisions

1. **Seeding.**

   | diffbandit (`lua/diffbandit/diff/word_diff.lua`) | Target | Port fresh / fix |

   | `M.tokenize`, `codepoint_at` | `by_word.lua` `inline_chunks` | `\r` is alpha; continuous script uses `unicode.lua`; reject invalid UTF-8 lead bytes by treating the byte as one code point |
   | `optimize_word_chunks` | `optimizer.lua` | — |
   | `split_word_blocks`, `should_merge` | `split.lua` | — |
   | `match_adjustment_delimiters`, `match_complex`, `compare_punctuation` | `by_word.lua`, `by_char.lua` | — |
   | `default_corrector` | `by_word.lua` | `TrimSpacesCorrector`, `IgnoreSpacesCorrector` (word level) |
   | `M.inner_fragments`, `M.compare_and_split` | `by_word.lua` `compare`, `compare_and_split` | policy argument |
   | `is_punctuation` | `trim.lua` | — |
   | (none) | `by_char.lua` | `ByCharRt`: `compare` (raw), `compareTwoStep`, `compareTrimWhitespaces`, `compareIgnoreWhitespaces`, `CodePointsOffsets` |
   | (none) | `unicode.lua` | `CharacterUtils.kt` range tables (other-alphabetic, ideographic, Hiragana, Katakana, Thai, Javanese, decimal digit) plus a generated BMP letter table (categories Lu, Ll, Lt, Lm, Lo, Nl) |

   - Code points are decoded once per text into an array of code points and their byte offsets. The UTF-16 surrogate logic in `CharacterUtils.codePointAt` disappears.
   - The letter table is generated by `openspec/changes/diff-engine-words/drafts/unicode_ranges.py` from `UnicodeData.txt` 16.0.0, then committed. Lookup is a binary search over range starts, like `binarySearchInRanges`.
2. **API additions** (`gleb.diff.engine`):

   ```lua
   ---@alias gleb.diff.Highlight "by_word"|"by_word_split"|"by_char"|"by_line"|"none"

   ---@class gleb.diff.InnerFragment  byte offsets, 0-based half-open, relative to the fragment's text
   ---@field start1 integer
   ---@field end1 integer          start1 == end1: insertion point on side 1
   ---@field start2 integer
   ---@field end2 integer

   ---@class gleb.diff.LineFragment
   ---@field inner? gleb.diff.InnerFragment[]  nil: whole fragment changed; {}: equal under the policy

   ---@class gleb.diff.Options
   ---@field highlight? gleb.diff.Highlight  default "by_word"

   ---@class gleb.diff.Limits
   ---@field max_inner_bytes? integer  per side, per fragment (default MAX_INNER_BYTES = 50000)

   ---@class gleb.diff.Column
   ---@field row integer        0-based line in that side's buffer
   ---@field col_start integer  byte column, 0-based
   ---@field col_end integer    exclusive; == col_start for an insertion point

   ---@param text1 string
   ---@param text2 string
   ---@param opts? gleb.diff.Options  (policy, limits)
   ---@return gleb.diff.InnerFragment[]
   function M.compare_words(text1, text2, opts) end
   function M.compare_chars(text1, text2, opts) end

   ---@param fragment gleb.diff.LineFragment
   ---@param side 1|2
   ---@param lines string[]  that side's lines
   ---@return gleb.diff.Column[]?  nil when fragment.inner is nil
   function M.inner_columns(fragment, side, lines) end
   ```

   - A fragment's comparison text is its lines joined with `"\n"`, plus a trailing `"\n"` when another line follows on that side. Inner offsets index into it.
   - `inner_columns` splits a range that spans a newline into one column range per row, and drops the newline byte itself.
   - `compare_words` and `compare_chars` return `{}` for equal texts. Whole-text results are not squashed, as in IntelliJ's `compareWords` and `compareChars`.
3. **Highlight modes and the pipeline.**
   - `none` returns `fragments = {}` without comparing.
   - `by_line` returns `compare_lines`, with `inner` nil everywhere except whitespace-only insertions and deletions, which get `{}`.
   - `by_word`, `by_word_split` and `by_char` run `createInnerFragments` per fragment. Then `processBlocks` runs with `squash = (highlight ~= "by_word_split")` and `trim = (policy == "ignore_whitespaces_chunks")`.
4. **Limits.** A fragment's inner comparison fails when:
   - either side's text exceeds `max_inner_bytes`;
   - the word or char LCS is too big (the `lcs.lua` status from `diff-engine-lines`).
   - A failed fragment keeps `inner = nil` and counts toward `MAX_BAD_LINES = 3`. From the third failure on, no further fragment is compared.
   - When the call deadline passes during the inner phase, the remaining fragments keep `inner = nil` and `timed_out` is set. The line fragments stay IntelliJ's; no xdiff fallback happens here.
   - The inner phase checks the deadline before each fragment and inside the LCS loops.
5. **Performance bound.**
   - The same generator as `diff-engine-lines` Decision 5, except that `lines2` replaces `compute` with `calculate` on every line with `i % 10 == 5`: 500 one-line modifications, no insertions or deletions.
   - With `highlight = "by_word"`, the median of 3 runs after a warm-up stays under 200 ms × `H.load_factor()`.
   - Each fragment then has the inner range of `compute` → `calculate`.
6. **Squash offsets.** As in `doSquash`, a later fragment's inner ranges are shifted by its text offset within the merged text, which counts the joining `"\n"`. A range that touches the previous one on both sides merges with it.
7. **Fixtures** (converter from `diff-engine-lines`, extended):

   | Source (`platform/diff-impl/tests/testSrc/com/intellij/diff/comparison/`) | Cases | Table | Checked through |
   |---|---|---|---|
   | `WordComparisonUtilTest.kt` (13 functions) | 58 `lines_inner` + 20 `words` | `intellij_words.lua` | `lines_inner`: `compare_lines` with `by_word` gives one fragment covering both texts, whose inner ranges match; `compare_words` matches too. `words`: `compare_words` |
   | `CharComparisonUtilTest.kt` (11 functions) | 65 `chars` + 3 `chars_raw` + 3 `chars_smart` | `intellij_chars.lua` | `compare_chars`; raw rows through `by_char.compare` |
   | `SplitComparisonUtilTest.kt` (3) and `LineComparisonUtilTest.kt` (1 `splitter`) | 27 | `intellij_split.lua` | `compare_lines` with `by_word_split`, or `by_word` for `squash = true` rows, and `ignore_whitespaces_chunks` for `trim = true` + IGNORE rows |
   | `TrimUtilTest.kt` | punctuation over U+0000..U+FFFF, about 18 alpha and continuous-script strings | `intellij_chars_classes.lua` | `trim.lua` classes |

   - A matching row stores changed byte offsets per side, and the check compares the union of the inner ranges as a set, as IntelliJ's `checkDiffMatching` does. A change-list row stores exact ranges.
   - UTF-16 offsets become byte offsets through the row's text. For example, `("汉语漢語" - "語汉语漢")` with changed chars `{3}` and `{0}` becomes bytes `{9,10,11}` and `{0,1,2}`.
   - **Property test.** `ComparisonUtilAutoTest`'s word, char and inner invariants, with the LCG and both alphabets of `diff-engine-lines`:
     - ranges are ordered and in bounds;
     - gaps are equal byte-for-byte under DEFAULT and without whitespace under the other policies; changed chunks are unequal byte-for-byte under DEFAULT and TRIM, and without whitespace under IGNORE;
     - no range splits a UTF-8 sequence;
     - inner ranges stay inside their parent's texts.

## Risks / Trade-offs

- **Letter table size.** The BMP letter table holds about 700 ranges, so `unicode.lua` is large data. It is loaded only when the engine tokenizes, and is never required at startup.
- **Squash differences.** The fixtures check `lines_inner` as one squashed fragment, which pins the squash offsets.
- **Byte vs UTF-16.** Converted fixtures could hide an off-by-one in the converter. The emoji alphabet in the property test catches split sequences.

## Renders

None. This change has no visible UI: it extends a pure library. Inner highlight colours (`DiffViewWord`) and their renders come with `diff-view`.
